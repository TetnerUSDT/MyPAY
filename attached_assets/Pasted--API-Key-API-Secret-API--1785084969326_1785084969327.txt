Да, одного API Key и API Secret недостаточно.
Они нужны только для аутентификации запросов к API (подпись в HTTP-заголовках). Для совершения выплат (GasFree-переводов) дополнительно требуется адрес Service-Provider (и обычно ещё verifyingContract).
Как получить адрес провайдера
Вызовите публичный эндпоинт:
textGET https://open.gasfree.io/tron/api/v1/config/provider/all
(для Nile-тестнета: https://open-test.gasfree.io/nile/api/v1/config/provider/all)
Параметры запроса: нет
Аутентификация: обычно не требуется для этого эндпоинта.
Ответ содержит список провайдеров. Пример структуры:
JSON{
  "code": 200,
  "data": {
    "providers": [
      {
        "address": "TQ6qStrS2ZJ96jcieJC8AutTxwqJEtmjfp",  // ← это serviceProvider
        "name": "Provider-1",
        "config": {
          "maxPendingTransfer": 1,
          "minDeadlineDuration": 60,
          "maxDeadlineDuration": 600,
          "defaultDeadlineDuration": 180
        }
      }
    ]
  }
}
Поле address — это и есть адрес Service-Provider, который нужно указывать при формировании сообщения авторизации перевода (serviceProvider).
Что ещё обычно нужно
В конфигурации (например, в SDK Tether WDK или при ручной сборке) обычно требуются:

В примерах Tether WDK для mainnet часто используют:

Но рекомендуется всегда брать актуальный список через API, потому что провайдеров может быть несколько и адреса могут меняться.
Краткий порядок действий

Получите API Key + API Secret в GasFree Developers Center (после одобрения заявки).
Вызовите /api/v1/config/provider/all → возьмите address нужного провайдера.
При создании авторизации перевода укажите этот serviceProvider вместе с остальными параметрами (token, user, receiver, value, maxFee, deadline, nonce и т.д.).
Подпишите сообщение от имени пользователя (EOA) и отправьте авторизацию через API провайдера.
