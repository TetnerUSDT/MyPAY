Техническое задание: Расширение админки для Telegram Bot
Общий обзор
В разделе "Telegram Bot" админки добавить вкладки:

Webhook: Вынести текущий функционал (настройка webhook для бота).
Команды: Настройка и добавление команд с реакциями.
Навигация: Настройка меню с кнопками.

Вкладка "Команды"
Функционал

CRUD-операции для команд: создание, редактирование, удаление, список.
Поля для команды: название (e.g., /start), описание, тип реакции.
Команда /start заложена по умолчанию с настройкой реакции по ней, например добавить фото и текст при нажатии на /start

Типы реакций

Текстовый ответ: Текст + опционально изображение + прикреплённые файлы (загрузка через админку).
Прикреплённый endpoint: Универсальная настройка URL endpoint (из внутренней БД или внешний). Endpoint возвращает данные (статистика, таблицы, текст) в JSON; бот парсит и форматирует в сообщение. Параметры: URL, метод (GET/POST), аутентификация, шаблон форматирования ответа.
Условные ответы (дополнительно): Логика if-then на основе user data (e.g., роль, статус). Универсально: правила (условие -> реакция), поддержка переменных из user context. Удобно для персонализации без кода.

Вкладка "Навигация"
Функционал

Настройка inline- или reply-клавиатуры для меню.
Регулируемая сетка: поля для рядов/колонок (e.g., 1xN, 3xM), drag-and-drop для позиционирования кнопок.
CRUD для кнопок: текст, позиция в сетке.

Прикрепления к кнопкам

Типы: документ, ссылка (URL), изображение, файл (загрузка), или ссылка на команду из "Команды" (выбор из списка).
Обработка: при клике бот отправляет прикреплённое или выполняет команду.


Типы реакций в вкладке "Команды"

Текстовый ответ:

Поле для текста (Markdown/HTML поддержка).
Опционально: загрузка изображения (URL или файл).
Опционально: прикрепление файлов (множественное, типы: PDF, ZIP и т.д.).
Отправка: бот отвечает сообщением с текстом, изображением и файлами.


Прикреплённый endpoint:

Поле для URL endpoint (внутренний/внешний).
Метод запроса: GET/POST.
Аутентификация: токен, API-ключ.
Параметры запроса: динамические (из user context, e.g., user_id).
Шаблон форматирования: Jinja-like для парсинга JSON ответа в текст/таблицу.
Отправка: бот запрашивает данные, форматирует и отправляет как сообщение.


Условные ответы:

Список правил: условие (e.g., user.role == 'admin') → реакция (любой тип выше).
Условия: на основе user data (ID, роль, статус, переменные из чата).
Логика: if-elif-else, приоритет по порядку.
Универсальность: поддержка скриптов (JS-like) для сложных условий.
Отправка: бот оценивает условия и выполняет соответствующую реакцию.

Вкладка "Навигация"
Функционал

Иерархическая структура меню: корневой уровень + подменю (вложенные уровни).
Тип клавиатуры: inline или reply (выбор для каждого меню/подменю).
Регулируемая сетка: поля для рядов/колонок (e.g., 1xN, 3xM), drag-and-drop для позиционирования кнопок в сетке.
CRUD для меню: создание корневого меню, подменю (привязка к кнопке родителя), редактирование, удаление.
Автоматическая кнопка "Назад": добавляется в подменю, возвращает к родительскому уровню (настраиваемый текст, позиция).

Кнопки в меню

CRUD для кнопок: текст, позиция в сетке, уровень (корень/подменю).
Типы действий по клику:

Открытие подменю (выбор существующего подменю из списка).
Документ, ссылка (URL), изображение, файл (загрузка).
Команда (выбор из раздела "Команды").


Обработка: клик на кнопку с подменю показывает его клавиатуру; "Назад" возвращает предыдущую.
